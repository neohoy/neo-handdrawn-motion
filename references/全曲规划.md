# 全曲规划：从歌到镜头表

## 1. 读歌

- **听段落**：`tools/analyze.py` 打印小节线（downbeats）、合并后的能量段和强拍。再对照 `tools/lyrics.py --show` 打印的每句歌词时间，把歌切成前奏、主歌、导歌、副歌、间奏、桥段、尾奏。
- **找重复**：副歌通常会重复。用 `tools/repeats.py <项目> <最后一遍副歌起> <止>` 找出其他几遍副歌的位置和时间差。得分 ≥ 0.4 就是同一段旋律。
  - 时间差稳定时，前几遍副歌可以复用最后一遍的画面，只换文字（写法见 `examples/风吹新竹/build_f3.py`，新工程用脚本参数区分变体）。
  - 歌词不同的句子要单独画，例如《风吹新竹》第一、二遍副歌的最后一句“原来我们都在这里长大”。
- **歌词时间的来源**（按可靠程度排）：
  1. 歌曲平台或生成工具给的 LRC；
  2. 用户提供的时间表；
  3. 用 `/media-use` 转写。

  拿到后用 `tools/lyrics.py` 转成 `assets/lyrics.json`，简体繁体都可以，成片按 `mv.json` 的 `script` 统一。
- **核对歌词时间**：对完副歌重复的位置，再核对每遍副歌同一句的时间差是否一致。不一致的那一句，原始时间可能有误。《风吹新竹》第一遍副歌最后一句就差了 0.8 秒。

## 2. 读歌词，设计画面

按 [歌词转画面](歌词转画面.md) 填 `设计/意象表.md`：
- 全片的主题、谁在唱、母题、角色、地点、颜色节奏；
- 逐句写出画面里有什么、歌词放在哪个版式组件上、要新画哪些素材。

然后在 `scripts/assets/` 里把角色和道具画出来，运行 `asset_sheet.py` 出素材表，自己先看一遍。

## 3. 定镜头表（写进 `mv.json` 的 `scenes`）

- **一个镜头约 2 句歌词、9–10 秒**，镜头内分两组，每句一组。很快的四句可以合成一镜（如四格漫画），很长的一句可以单独一镜。
- **切点**放在下一句开唱前约 0.2 秒，或者落在最近的强拍上。镜头首尾相接，从 0 一直铺到歌曲结束，不能有空档。
- **故事线**：从意象表的一句话主题出发，给每段分配“谁、在哪、做什么”。《风吹新竹》的线索是：
  - 童年的街巷（主歌一）；
  - 夜里的园区和公路（导歌）；
  - 阵风里的副歌；
  - 长大后加班、看海（主歌二）；
  - 九降风和时光流逝（间奏）；
  - 去了不同城市（桥段）；
  - 那年的海浪和最亮的家（最后一遍副歌）；
  - 照片活过来、风筝飞进星空（尾奏）。
- **底色节奏**：相邻镜头的底色要拉开。副歌用最饱和的颜色，前奏和尾奏回到米白纸。
- **纯音乐段**不能空着，用这首歌里的东西做陈列、时光流逝这类不需要歌词的镜头填上（见 `镜头配方.md`）。

`mv.json` 里一个镜头的写法：

```json
{"id": "s02-dusk-gate", "start": 10.22, "end": 19.43, "builder": "scripts/scenes/s02-dusk-gate.py", "args": []}
```

同一个脚本要生成两个变体时（例如副歌一、二各一个“长大”），给两条记录配不同的 `id` 和 `args`。脚本读 `sys.argv` 决定 `id`、前缀和歌词序号。

## 4. 写成分镜给用户看

正式开工前，把镜头表写成 `STORYBOARD.md`，每个镜头一行：时间、段落、歌词、画面、歌词放在哪。连同素材表 `设计/素材表.png` 一起给用户看，这是第一个需要用户确认的检查点。

用户点头后，先做 1–2 个代表性镜头（建议一个主歌镜头 + 第一遍副歌），渲染成样片给用户看，这是第二个检查点。画风和节奏确认后，再铺开做全片。
